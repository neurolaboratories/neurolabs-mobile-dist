# neurolabs-mobile-dist

Partner-facing distribution repository for Neurolabs mobile SDK artifacts.

This repository is the single release entry point for:

- iOS (`NeurolabsSDK`) via Swift Package Manager binary package
- Android SDK artifacts (AAR/zip) via GitHub Release assets
- Cordova plugin package (`.tgz`) via GitHub Release assets
- Integration guide markdown/PDF snapshots for iOS, Android, and Cordova

## Release Policy

- Releases are versioned with a shared tag: `vX.Y.Z`
- Each release is intended to contain matching iOS, Android, and Cordova artifacts
- Source repositories publish artifacts and notify this repo via CI (`repository_dispatch`)
- This repo updates manifests and publishes/updates the coordinated release metadata
- A release is created as a **draft** and is only tagged and published once
  `scripts/validate_release_ready.py` confirms all three platforms landed. The
  tag is created once, on the commit carrying the finished manifest, and is
  never force-moved.

## Release lines

Maintenance backports ship out of chronological order: `v1.6.12` was published
on 2026-09-21, five days *after* `v1.7.7`, and is five days newer and one minor
line older. Two consequences the tooling now handles explicitly.

**Manifests are line-aware.** `manifests/<platform>.json` carries both:

| Key | Meaning |
|---|---|
| `latest` | the highest version this repo has ever published — only ever moves forward |
| `lines["1.7"]`, `lines["1.6"]`, … | the head of each `MAJOR.MINOR` release line |

A backport records itself under its own line and leaves `latest` alone.
`scripts/update_platform_manifest.py` enforces this with a real semver compare
and refuses to move a line backwards. Consumers that want a specific line
should read `lines["1.6"]`; consumers that want the current release read
`latest`.

**`Package.swift` serves one line only.** Every `binaryTarget` must resolve to
the same `/releases/download/<tag>/` segment, asserted by
`scripts/verify_spm_manifest.py` after every stamp. The 1.6.x source tree has
no `RecognitionEngine` / `RecognitionEngineQdrant` / `RecognitionBootstrap`
targets, so this manifest cannot describe both lines, and the release train
**rejects** an iOS dispatch that does not carry an asset for every declared
target. Shipping an SPM package for a 1.6.x backport therefore requires a
`release/1.6` branch in this repo holding its own `Package.swift`; partners
pinning that line pin the branch or the tag, and `main` stays 1.7.x.

## iOS (SwiftPM)

### Add the package in Xcode

1. `File` -> `Add Package Dependencies...`
2. Use this repository URL:
   - `https://github.com/neurolaboratories/neurolabs-mobile-dist`
3. Select the version/tag you need (for example `v1.1.0`)
4. Add product:
   - `NeurolabsSDK`

### Swift import

```swift
import NeurolabsSDK
```

### On-device recognition products (v1.7.x)

On-device recognition is optional and ships as its own set of xcframeworks.
Add **one** product:

| You want | Add this product |
|---|---|
| The full provider chain (config gate → tenant discovery → snapshot → embedder → index → provider) | `RecognitionBootstrap` |
| Only the protocols/snapshot types, to implement your own provider | `RecognitionInterface` |

`RecognitionBootstrap` carries its complete link closure — `RecognitionEngine`,
`RecognitionEngineQdrant`, `NLQdrantEdgeFFI` and `RecognitionInterface` — so
there is nothing else to add by hand. Qdrant Edge is the only on-device vector
engine (USearch was removed in August 2026), and `NLQdrantEdgeFFI` is the ~13 MB
Rust dylib it links; `RecognitionEngine` on its own has no index implementation
and will not run recognition.

```swift
import RecognitionBootstrap
```

### Notes

- The root `Package.swift` is a SwiftPM binary manifest that points to the iOS XCFramework zips in this repo's release assets.
- CI updates the binary URLs and checksums automatically when an iOS release is published.
- CI stamps **URLs and checksums only** (`scripts/update_spm_manifest.py` rewrites
  matched `.binaryTarget` blocks in place). The `products:` section — including
  each recognition product's link closure — is hand-maintained and is not
  regenerated by a release, so edits there survive the release train.
- Stamping is **all-or-nothing**: one invocation stamps every `binaryTarget`
  declared in the manifest, and fails if the dispatch carries no asset for one
  of them. There is no way to stamp a subset.
- `scripts/verify_spm_manifest.py` then asserts every `binaryTarget` shares one
  release tag and runs `swift package dump-package` to prove the manifest still
  parses and every product's targets resolve. Run it after any hand edit:

  ```bash
  python3 scripts/verify_spm_manifest.py Package.swift
  ```

### Repairing a split `Package.swift`

Run the **Manual Dist Promote** workflow with just `version` set (leave
`stamp_spm` on, leave the asset URLs blank). It downloads every asset published
on that tag, recomputes each checksum from the bytes actually being served,
stamps all seven `binaryTarget`s, and runs the assertion above. It fails loudly
if the release is missing an asset for a declared target rather than stamping
what it can.

## Android

Android artifacts are published as release assets in this repository (for example `.aar` files).
This repo also supports Android Maven metadata in `android_ready` dispatch payloads and persists it in `manifests/android.json` (repository URL + coordinates) while still mirroring the AAR into this dist release.
Maven registry publishing is currently disabled in the release automation for this repo. Any `latest.maven` coordinates and Gradle Maven snippets are informational metadata only and are not guaranteed to be resolvable from GitHub Packages.

### Typical integration (local AAR)

1. Download the `.aar` from the matching release tag
2. Add it to your app (for example under `app/libs/`)
3. Reference it from Gradle

Example:

```gradle
repositories {
    flatDir {
        dirs("libs")
    }
}

dependencies {
    implementation(files("libs/neurolabs-android-sdk-vX.Y.Z.aar"))
}
```

Refer to `manifests/android.json` for:
- mirrored AAR release asset URL + checksum
- optional Maven repository/coordinates (`latest.maven`)
- Gradle Maven snippets (`gradle_maven_repository_example`, `gradle_maven_dependency_example`)

## Cordova

Cordova plugin packages are published as release assets (`.tgz`).

### Custom camera parity notes

Recent Cordova + Android SDK releases add/expand custom camera IQ parity configuration support (exact field passthrough depends on the Cordova plugin version in the tag), including:

- `validationPreset` (including `ios_parity` on Android)
- live quality toggles (`liveQualityChecksEnabled`, `liveQualityTargetFps`)
- capture preview/review toggles (`showCapturePreview`, `showPreviewInStrictMode`, `freezePreviewOnCapture`)
- `customCameraTemplate` message/style/layout fields (banner, issue strip, review panel) (currently Android passthrough-first; iOS availability depends on SDK bridge model version in the tag)

When consuming new Cordova plugin builds from this dist repo, ensure the Android/iOS native SDK artifact versions in the same release tag support the requested fields.

Support summary (current parity state):

| Capability | Android (Cordova) | iOS (Cordova) |
|---|---|---|
| Custom camera IQ route from `openCamera` | Yes | Yes |
| Live quality checks + issue/banner feedback | Yes | Yes |
| Preview/review toggles | Yes | Yes |
| Template messages/labels/priority | Yes | Yes |
| Template banner style/placement/animation | Yes | Yes |
| Template review style | Yes | Yes |
| All template fields applied identically | No (platform-specific UI/runtime differences remain) | No |

iOS notes:
- `bannerMessageStrategy` is transported but not applied (iOS uses native template banner logic).
- Some Android-only issue strip tint semantics are not applied on iOS.

### Install from a release asset

```bash
cordova plugin add https://github.com/neurolaboratories/neurolabs-mobile-dist/releases/download/vX.Y.Z/neurolabs-cordova-sdk-vX.Y.Z.tgz
```

Refer to `manifests/cordova.json` for the latest package URL and checksum.

## Integration Guides

Generated guide snapshots live under:

- `docs/integration-guides/latest/<platform>/`
- `docs/integration-guides/releases/vX.Y.Z/<platform>/`

Guide metadata and PDF checksums are tracked in:

- `manifests/guides.json`

Before publishing a new coordinated mobile-dist release, refresh the guides from the SDK source repos:

```bash
python3 scripts/sync_integration_guides.py \
  --dist-root . \
  --workspace-root .. \
  --version vX.Y.Z \
  --fail-if-pdf-stale
```

Notes:
- This copies the source markdown + PDF rules from `neurolabs-cordova-sdk`, `neurolabs-android-sdk`, and `neurolabs-ios-sdk`.
- It then generates deterministic PDFs with the built-in `scripts/generate_markdown_pdf.py` helper, so refresh does not depend on `pandoc` or third-party Python packages.
- CI automation for the same step is available in `.github/workflows/refresh-guides.yml`.

## Machine-Readable Manifests

This repo includes metadata files for automation and partner tooling:

- `manifests/ios.json`
- `manifests/android.json`
- `manifests/cordova.json`
- `manifests/guides.json`

These files track the latest known version, release asset URL, and SHA256
checksum for each platform, plus a `lines` map with the head of each
`MAJOR.MINOR` release line (see "Release lines" above). Automation that wants
"the current release" should read `latest`; automation pinned to a maintenance
line should read `lines["1.6"]` and must not assume `latest` tracks it.

## CI/CD in This Repo

Real workflows used in this repo:

- `.github/workflows/dist-release.yml`
  - receives `ios_ready`, `android_ready`, `cordova_ready`
  - updates manifests and iOS `Package.swift`
  - creates/updates the coordinated release metadata
- `.github/workflows/manual-promote.yml`
  - manual fallback for recovery or backfill
  - re-stamps `Package.swift` in full from the assets published on a tag
    (`stamp_spm`), for repairing a split manifest

Shared tooling:

| Script | Role |
|---|---|
| `scripts/semver.py` | semver parse/compare/line helpers — never compare tags as strings |
| `scripts/update_platform_manifest.py` | monotonic, line-aware `latest` for `ios`/`android`/`cordova` |
| `scripts/update_spm_manifest.py` | all-or-nothing `binaryTarget` stamping |
| `scripts/verify_spm_manifest.py` | one-release-line assertion + `swift package dump-package` |
| `scripts/validate_release_ready.py` | 3-platform readiness gate; runs **before** anything is committed or tagged |

## Integrity Verification

Consumers can validate downloaded artifacts using the SHA256 values in the corresponding manifest files.

## Support / Coordination

Use the same release tag (`vX.Y.Z`) across all Neurolabs mobile components when integrating a coordinated version.
